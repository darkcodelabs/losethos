LoseThos Memory Scheme

LoseThos will always identity map virtual to physical because that's what makes 
LoseThos, LoseThos, along with running everything in highest privilege level.

Fragmentation is inevitable unless the alloc/free pattern repeats, but I've 
never had problems.  LoseThos is not aiming for running without rebooting.  In 
fact, you could reboot before running every application, if you wanted to, with 
the soft boot, Boot().  It takes 2 seconds.

Typing and repeatedly #includeing code at the command line leaks.  It's tiny.  
Kill the task with CTRL-ALT-X and spawn a new one with CTRL-ALT-E periodically, 
if you're worried about it.  Icons in your personal menu can be set to pop-up a 
new task for the application and die when finished, returning memory and 
avoiding leaks.

I experimented with garbage-collection in the sense of merging freed chunks into 
bigger chunks, but it created instability that was horrible.  From my 
experience, the best strategy is to leave freed chunks the same size so they can 
be reallocated because that's the real world.  I'm guessing the buddy allocation 
technique wouldn't work as well as the current one.

LoseThos' memory scheme doesn't work in theory, but works in practice.
