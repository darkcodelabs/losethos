Writing a PC Operating System, Part 1

                                       by

                                  Terry Davis

                               Author of LoseThos





The first step to writing an operating system is getting to "ring 0".  Ring 0 is 
the CPU mode where you have full access to the computer.  Windows and Linux try 
very hard to keep you from getting to ring 0, for security reasons.  In fact, 
many people would tell you that an operating system's most important mission is 
to keep you out of ring 0.  There are two, possibly three, ways to get to ring 
0.  You can write code that runs at boot time, you can use an operating system 
which has no protections, like DOS or LoseThos, or you might be able to get 
permission from Windows or Linux if you write some kind of driver kludge.  You 
can probably search on the web for such a thing.

I started LoseThos in 1993 when I was running DOS, so I had nothing preventing 
me from making an operating system that launched like an application (never to 
return).  When I resurrected the code and started working again in 2003, I had a 
problem!  I solved my problem by installing FreeDOS and merrily launching my 
operating system just like any application.  When I began, it was all assembly 
language and I used TASM, an assembler by Borland.

You have to know a little assembly language to write an operating system because 
you have to execute a few special instructions, here and there.  It's a horrible 
shame that you have to know 16-bit real mode assembly language.  Real mode is 
awful and archaic, but, unfortunately, systems boot in real mode.  You honestly 
need just enough to get you to long (64-bit) mode.  Even 32-bit protected mode 
is a shame to waste your time learning, but it's almost like 64-bit long-mode.  
It's possible Atom chips or something might regress to 32-bits.  Don't be 
mislead by the people who suggest you worry about old hardware -- you've got 
more than enough to deal with looking forward and by the time you finish your 
operating system your current computer system will be old!

Assembly is macho and impressive to beginners, but to seasoned programmers it's 
silly, except when necessary.  You'll need to do a 16-bit boot loader, code to 
switch to 32-bit, and, then, 64-bit mode and a few odds and ends.  You'd be 
hard-pressed to find a 16-bit C compiler for the boot loader and there is a size 
limit for boot loaders of 512 bytes, so hand assembly is pretty-much mandatory 
for boot loaders.  All you need to know for boot loaders is BIOS INT 13h, AH=42h
.

You might wish to start with the FreeDOS approach.  Eventually, you'll want to 
do a proper boot loader.  You'll soon discover that other operating systems 
don't like you rewriting to the master boot record at block zero or writing to 
the partition boot records at the start of each partition.  DOS or LoseThos will 
readily allow you to write to block zero.  That's needed for hard-drive booting. 
 You'll need to do a CD-ROM ISO file before the hard-drive, probably.  (At this 
stage in LoseThos development, I had a floppy drive, but times have changed.)  
It's critical that you can back-up to CD-ROM or something else, especially when 
developing disk code.  Burning CD-ROMs or making ISO files requires learning the 
format for CD-ROMs.  You need to study the ISO9660 file system and El Torito 
booting.  The boot block is around block number 16-20 and it's 2048 bytes 
instead of 512.  LoseThos can make a bootable CD-ROM image.  See CDFileCreate 
and CDBootFileCreate.

If you're thinking of USB memory drives, you can use BIOS calls, so I'm told, 
but you'll face the monster challenge of doing a USB driver if you want to avoid 
leaving 64-bit long mode to call the BIOS.

Speaking of having enough to worry about looking forward, there is a new booting 
convention that is starting, UEFI.  Supposedly it will be backward compatible.  
I don't know much about it, except it sucks for LoseThos because it requires PE 
or ELF files and while my LoseThos compiler makes propriatery executables.

LoseThos isn't really intended to make making other operating systems easy, but 
it offers the feature of no protections.  However, its assembler has limited 
16-bit support.  You can study LoseThos code, if you don't want to do it by 
yourself.  LoseThos code is public domain, so there are no strings attached.

CD-ROM Boot Sect:
::/LT/Opt/Boot/BootCD.SPZ

Hard Drive Partition Boot Sect:
::/LT/Opt/Boot/BootHD.SPZ

Master Boot Sect and Stage 2 Master Boot Loader:
::/LT/Opt/Boot/BootMHD.SPZ
::/LT/Opt/Boot/BootMHD2.SPZ

My boot loaders get patched with the Logical Block Addres (LBA) of my kernel 
file and the size of the kernel file when I install my operating system.  
InstallBoot().  My boot loaders don't mess around with file system details.  My 
boot loaders hand-off ctrl to my kernel while in real 16-bit mode so my kernel 
can make BIOS calls before switching to 32-bit, then 64-bit modes.

See my kernel start-up code for details on making BIOS calls and switching to 
64-bit mode:
::/LT/OSMain/OSStartUp.CPZ
