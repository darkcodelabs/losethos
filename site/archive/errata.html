• I said "pound" when I meant "number sign".  I think I
    misunderstood someone once and got that stuck in my head.  
    Reminds me of a meat tenderizer or potato masher.  Maybe,
    it was from a machine which had a pound key instead of a
    number key, I don't know.
  • I said "free form bitmap".  The graphics are more or less
    scalable vector graphic with no boundary, though they can
    be made into bitmaps.
  • I said "30,000" lines for the compiler and kernel.  It's
    more like 40,000.
  • I said "4 Meg" for the bible.  That's uncompressed.  It's
    more like "1 Meg" because it's stored compressed.  The
    "LTZ" program which runs on Windows, however, is 4 Meg and
    is pretty-much unrelated to LoseThos.  LoseThos, itself, is
    1.7 Meg.
  • The compiler feeds line-by-line at the command line, but
    you don't need to limit commands to one line because it
    waits until you complete command, even if it takes multiple
    lines.  You can even enter functions at the command line.
  • The map files hold source-line information and aren't
    actually where symbols are defined.  Symbols are actually
    stored in a table of imports and exports in each binary
    file.  Just-in-time (dynamically) compiled code defines
    symbols and line numbers immediately.

  • "AdamK" stands for "Adam Kernel"
