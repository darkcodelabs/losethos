Making LoseThos...
    Back in 1993, I got a 486 computer and wanted to make a protected mode operating
system.  Books on the 386/486 architecture were plentiful, as well as on all things BIOS and
DOS.  If you're young, you're at a disadvantage -- old people actually programmed in 16-bit
segments.  You young people will have to waste time learning 16-bit programming which
really sucks for you.
   First, some history.  I started programming in assembly language in 1983, in eighth
grade on a Commodore 64. 6510 (6502).  It was mandatory because the alternatives were
so slow.  I continued and in 1990 got a job programming in VAX assembly on a proprietary
operating system for Ticketmaster.  I took a course on x86 asm programming, kinda a joke
for me, like many courses, but I got credit.  I learned a couple things in that course, like
B800 for text screen memory and "Push BP; Move BP,SP".  In an architecture course, we
studied VAX architecture and the instructor was asked what happens in a CASE statement
when the range is exceeded.  At the time I was getting paid to do VAX asm programming
and said "It goes to the statement following the CASE."  I know so many architectures, it's
funny.  These are the architectures I've programmed professionally in pure assembly
language on: VAX, 68000, 386, 8051, ARM, PIC.  I also know 6800, 6502.  I am highly
trained and experienced for embedded systems programming.  I studied hardware and
software and even decided to get a masters in electrical engineering.  My specialty is
where software meets hardware -- reading data sheets to know how to twiddle the bits of
the hardware registers.  In a course, we made a simple CPU in a simulator with microcode
so I understand digital hardware as well, and I've made a few circuit boards at work.
   Anyway, in 1993, I wrote just enough code to switch to protected mode and echo
keystrokes on the screen.  That was written with turbo assembler and launched as a regular
application from DOS.  DOS runs in real mode so you have kernel privilege.  It was a little
tricky making the real/protected mode switch because you have to get several things right
for it to work.  It's always easier if you can take baby steps and sucks when many things
must be right, all at once.  You learn to check various status registers when available and
go sideways a little, when necessary, to uncover things you need indirectly.
   I set that code aside in 1993 and resurrected it again in 2003 when the 64-bit
architecture was fresh.  I thought, "Now's the opportunity for a new legacy free system, if
ever there was."  Unfortunately, I didn't own a 64-bit CPU for a couple years, but things
turned-out okay.   I had to run my 1993 program -- you can't run it from Windows because it
won't allow you kernel privilege.  I downloaded FreeDOS and launched it from there.
   I had done expression evaluators numerous times for work and had taken a course on
compiler in school and had written an assembler for the 8051 in about 3 days, so I was not
intimidated by writing compilers -- my boss at Ticketmaster had written a PASCAL
compiler and I made a couple mods to it, and of course our assembler and linker were
written by coworkers.  I had written a C interpreter for SimStucture, an edutainment thing in
made in 2000.  Anyway, I wrote an interpreter for my operating system even before I had a
file system.  I put the source code for script files I wanted to compile(interpret) in ASCII in
my binary file.  When it started-up, it compiled half of itself.  I added a file system, made it
boot from floppies, made it a true compiler by in-lining byte codes.  Then, optimizing.  I
switched everything to 64-bit in about 2005 when i got a 64-bit computer, got rid of the
floppy, added CD-ROM, etc.
   Other people will tell you different ways to make an operating system, if you ask them.

    God there are some obnoxious stupid fuck people out there -- this dude thinks a
protected mode operating system uses BIOS calls or something.  It's from scratch, bare
metal on hardware, not even a compiler or assembler not from scratch!  The BIOS won't run
in protected mode, you fool, let alone 64-bit mode.  It's a rude shock for people when they
encounter people smarter than themselves.  I've been blessed to be around plenty of really
smart people.
